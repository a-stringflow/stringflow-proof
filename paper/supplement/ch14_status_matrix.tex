\section{Theorem-by-theorem status matrix}

This chapter records the status of every theorem consumed by the main
chain.  The matrix is organised by file.  The statuses are the current
audit state; they are re-checked whenever the repository changes.

\begingroup
\setlength{\tabcolsep}{4pt}

\subsection{Legend}

\begin{itemize}[leftmargin=*]
\item \textbf{Math: proven}: the mathematical argument is written out
  in this paper or the manual.
\item \textbf{Lean: compiled}: the Lean theorem compiles without
  \texttt{sorry}.
\item \textbf{Lean: pending}: the Lean theorem is not yet closed.
\item \textbf{compiled (conditional)}: the theorem compiles but
  consumes an open input such as \texttt{unifiedCoreClosed} or
  \texttt{failureWindowExistence}.
\end{itemize}

\subsection{How to update the matrix}

The matrix is updated only after the following checks:
\begin{enumerate}[leftmargin=*]
\item \texttt{lake build} passes for the affected files;
\item \texttt{\#print axioms} returns only the allowlist for the
  affected theorems;
\item the \texttt{sorry} search is re-run for
  \texttt{UnifiedCoreAudit.lean};
\item the \texttt{native\_decide} search is re-run for the main chain.
\end{enumerate}
No row is promoted from pending to compiled on the basis of this
document alone.
